# Zuse Native (iOS and Mac)

SwiftUI app for iPhone, iPad and Mac. It pairs with a computer running Zuse
(QR code, link or SSH) and drives chats over the Rust canonical RPC contract.

## Layout

| Path | What it is |
| --- | --- |
| `App/` | SwiftUI app shared by the `Zuse` (iOS) and `ZuseMac` targets |
| `Sources/ZuseCore/` | Protocol, transport and presentation logic (Swift package) |
| `Tests/ZuseCoreTests/` | `ZuseCore` unit tests |
| `UITests/`, `MacUITests/` | UI tests against the RPC fixture |
| `config/deployment-profiles.json` | Cloud API URL and WorkOS client ID written into `Info.plist` |
| `Native/ZusePairing.xcframework` | Rust encrypted pairing channel (built locally, ignored by Git) |
| `Zuse.xcodeproj` | Generated by `scripts/generate-project.rb`; don't edit it by hand |

## Setup

Requires macOS with Xcode, a Rust toolchain from `rustup`, Ruby with the
`xcodeproj` gem (`gem install xcodeproj`) and Bun (runs the RPC fixture).

```bash
# Build the pairing XCFramework (installs the Apple Rust targets on first run).
python3 apps/ios/scripts/build-pairing-apple.py
open apps/ios/Zuse.xcodeproj
```

Rebuild the XCFramework after changing `crates/mobile-bridge`.

## Changing the project

After adding, removing or renaming Swift files, or changing build settings or
`config/deployment-profiles.json`, regenerate the project:

```bash
ruby apps/ios/scripts/generate-project.rb
```

Output is deterministic: rerunning it without source changes leaves
`project.pbxproj` unchanged, so a diff means something really changed.

## Checks

| Command | Runs |
| --- | --- |
| `bash apps/ios/scripts/check.sh` | swift-format lint, project consistency, `ZuseCore` tests against the RPC fixture, Mac and iOS Simulator builds |
| `bash apps/ios/scripts/test-simulator.sh [destination]` | iOS UI tests (defaults to iPhone 17 Pro) |
| `bash apps/ios/scripts/validate-apple.sh` | Everything above plus Mac, iPhone and iPad UI tests, with logs under `.context/native-apple-validation/` |
| `bash apps/ios/scripts/test-portable.sh` | `ZuseCore` tests that also run on Linux |

On Linux, `check.sh` runs the lint, project check, syntax parsing and portable tests.

Automated checks don't cover a live account or device, visual comparison,
accessibility or rendering performance. Check those by hand before a release.

## Bundled resources

These files in `App/` are committed snapshots that nothing in this repository regenerates:

- `UIParser.js`: generative UI spec parser, run in JavaScriptCore by `UISpecView`.
- `Mermaid.js` and `Mermaid-LICENSE.txt`: Mermaid 11.15.0 for `Diagram.html`.

They came from the original TypeScript workspace (see
`internal-docs/mobile-import.md`).

## Debug launch arguments

Debug builds read these to open a screen in a given state, for screenshots and manual checks
(`xcrun simctl launch <udid> com.zuse.sh <arguments>`):

| Argument | Shows |
| --- | --- |
| `--native-preview` | Sample chat, projects and models, offline |
| `--home-preview`, `--zapper-preview` | Sample chat list, sample Zappers |
| `--tab=<zappers\|chats\|prs\|more\|search>`, `--more=<page>` | A tab, a More page |
| `--focus-composer`, `--draft=<text>` | The open chat (or `--new-chat-preview`) with the keyboard up and a draft |
| `--model-sheet-preview` | Model and reasoning settings |
| `--new-chat-preview`, `--setup-progress-preview`, `--cloud-preview` | New chat, its setup progress, cloud launch with a signed-in account |
| `--pairing-preview`, `--connection-preview=<connecting\|reconnecting\|attention>` | Add computer, a computer connecting, dropping out or unreachable |
| `--empty-preview` | A computer with no chats, Zappers or pull requests |
| `--loading-preview` | The same computer while its lists are still arriving |
| `--new-zapper-preview`, `--new-zapper-starter=<0-2>` | New Zapper, blank or from a first-run idea |
| `--new-zapper-submit=<model>` | Picks that model and presses Create (checks creating against a paired computer) |
| `--zapper-thread-preview` | The first Zapper's working thread, opened from the iPad Zappers list |
| `--show-sidebar` | The Mac sidebar over a narrow window |
| `--expand-activity`, `--expand-steps`, `--running-preview` | Open activity, open steps, a turn in progress |

`SIMCTL_CHILD_ZUSE_PAIR_LINK=<invitation>` pairs with a computer at launch, and
`--open-chat=<id>` then opens one of its chats.

Cloud chats take their repositories, agents and models from the cloud API's
`/v1/cloud/context`, so nothing about cloud launch is bundled. Agent sign-in for cloud
chats happens in the desktop app. Run with `--native-preview --new-chat-preview --cloud-preview`
to see cloud launch against built-in fixtures.

## Chat previews

`--native-preview --conversation-preview` opens a sample chat written as Rust transcript
entries (`App/PreviewConversation.swift`), so it renders through the same
`CanonicalTranscript` and `ChatTimeline` path as a connected computer. Add
`--running-preview` for a turn in progress, `--expand-activity` and `--expand-steps` to open
the work behind each turn, and `--transcript-top` to start at the first message.
`--large-transcript` loads 10,000 messages in the older record shape. With a paired computer
(`SIMCTL_CHILD_ZUSE_PAIR_LINK`), `--open-chat=<id>` opens one of its chats and `--show-changes`
then opens its changes.

## Chat panes

Every chat page is a row of pages: the conversation first, opened panes after it and the
pane picker last (`App/ChatPanePager.swift`, `App/ChatPaneViews.swift`; the page rules are
`ChatPaneDeck` in `Sources/ZuseCore/ChatPanes.swift`). Swipe sideways between pages. Pinch,
or press the header's panes button, to zoom out to cards: tap a card to bring it back, swipe
a card up to close it (the Mac shows a close button on each card). The chat and the picker
can't be closed. Panes are saved per chat; terminals keep running on the computer and
reattach after a relaunch.

| Pane | Shown for | Engine methods |
| --- | --- | --- |
| Threads, Pull requests, Issues, Docs, Overview | A Zapper's conversation | `WatchZappers`, `ZapperFiles` |
| Changes, Pull request | An ordinary chat with a checkout (pull request only when it has one) | `GetCheckoutDiff`, pull request methods |
| Terminals | Any chat on a current engine | `ListTerminals`, `OpenTerminal`, `SubscribeTerminal`, `WriteTerminal`, `ResizeTerminal`, `CloseTerminal` |
| Files, and each file opened from it | Any chat on a current engine | `ListWorkspaceDirectory`, `SearchWorkspaceFiles`, `ReadWorkspaceFile` |

Under the picker grid, a **New thread** action (like desktop's "+ New tab") starts a fresh
chat parented to this one (`parentChatId`), in the same project, folder and branch and with
the same agent configuration, then opens it (`createChat` via `Mutate`).

The terminal (`App/TerminalPane.swift`, `TerminalScreen` in ZuseCore) handles SGR colours
and attributes, cursor movement and erasing, scroll regions, the alternate screen, bracketed
paste, application cursor keys and cursor and device queries. It doesn't draw line-drawing
charsets, report the mouse or rewrap lines on resize.

Debug arguments for every state, offline with `--native-preview` (add `--zapper-preview
--zapper-detail-preview --zapper-chat-preview` for a Zapper's conversation, or
`--conversation-preview` for an ordinary chat), or with a paired computer and
`--open-chat=<id>`:

| Argument | Shows |
| --- | --- |
| `--panes-preview` | Sample panes beside the chat (live terminals and files with a computer) |
| `--pane=<kind>` | That pane in front: `threads`, `pullRequests`, `issues`, `terminal`, `files`, `docs`, `overview`, `changes`, `pullRequest`, `file` or `document`; `selection` for the picker, `main` for the chat |
| `--pane-overview` | The cards overview |
| `--pane-keyboard` | The terminal's keyboard and key bar |
| `--terminal-type=<command>` | Types a command and Return into the terminal once it is live |
| `--pane-hint` | The one-time "Swipe or pinch" hint, which `--panes-preview` otherwise skips |

`ChatPanesTests` covers paging, the overview, closing a pane and the picker offline;
`testLiveFilesAndTerminal` runs against a computer when `TEST_RUNNER_ZUSE_PANES_PAIR_LINK`
and `TEST_RUNNER_ZUSE_PANES_CHAT` are set.
