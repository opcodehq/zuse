Zuse supports two related ways to divide work. They solve different problems and have different isolation boundaries.

## In-conversation subagents

An agent can delegate a bounded investigation or implementation step inside the current conversation. Zuse shows that work as its own subagent activity instead of mixing it into the parent's stream, with a chip you can open in the side pane to follow its prompt, tools, and result.

Where the subagents come from depends on the agent:

- **Claude Code**: Task subagents, including background subagents that keep running after the parent turn ends.
- **Codex**: child agent threads.
- **Cursor**: the full nested transcript of each subagent.
- **Devin**: Devin Fusion's sidekick, shown as a **Sidekick** chip for each handoff.
- **OpenCode**: child sessions.
- **Zuse agent**: bounded child agents.

Running subagents and background tasks also appear in a background work row in the tray, where **Open agent** jumps to one.

These subagents use the parent session's environment. They're useful for focused research, test analysis, or a second opinion, but they are not a substitute for a separate worktree when several agents will edit concurrently.

## Claude Code workflow runs

When Claude Code runs a workflow, the transcript shows it as a compact summary and its agents open in the right pane. The board lists each phase with its agents and completion count. Select an agent to inspect its prompt and result, or use **View script** to read the workflow source when it's available. Progress depends on what Claude Code reports; a declared phase can appear before its agents start.

## Delegated chats

An agent can also start and steer other Zuse chats with Zuse's chat tools; see [Agent orchestration](/composer/orchestration). A delegated chat keeps its own conversation history, status, and agent, and records the chat that created it as its parent.

## Give bounded assignments

A useful delegation prompt names an outcome, a boundary, and the evidence expected back. For example:

> Inspect the session recovery path. Do not edit files. Return the likely failure points, the tests that cover them, and any unanswered question.

For editing work, add exclusive ownership:

> Own the settings form and its tests only. Do not edit the shared navigation components. Run the focused checks and report every changed file.

Do not assign overlapping write scopes unless one agent is explicitly responsible for integration. See [Run agents in parallel](/composer/parallel-agents/) for isolation and shared-checkout guidance.

## Review before accepting

A completed delegated task is evidence, not automatic acceptance. Open its chat or subagent transcript, inspect the files and commands it reports, then ask the coordinating agent to reconcile conflicts and run the cross-cutting checks. Review the combined diff in **Changes** before committing or opening a pull request.

Delegation cannot bypass Plan mode, access levels, or sensitive-path protection. Read [Agent orchestration](/composer/orchestration/) before allowing an agent to create or steer more work.
