## Goal

Make an MCP server's tools available to Zuse agents, then verify them in a fresh chat.

## How agents get MCP tools

Zuse gives every agent it launches the same plugin gateway tools (`plugins_list`, `plugins_search`, `plugins_schema`, and `plugins_call`). The gateway serves the plugins connected to your workspace in **Settings → Plugins & MCP**, hosted and local alike, so the same tools work with every supported provider.

Servers you already configured in an agent app on this computer are a separate source. Zuse can find them and copy them into Plugins with **Import from this computer**, so every agent gets them, not only the app where you set them up.

## Prerequisites

- Sign in to Zuse. Plugins belong to your personal workspace or an organization.
- Have the server's HTTPS URL, or a local `stdio` command configuration. Local commands must be installed on the computer running Zuse.
- Know how the server authenticates: sign-in (OAuth), no authentication, or a key sent as a bearer token or in a custom request header.
- Read the server's tool list and trust boundary before connecting it.

## 1. Add a remote server

1. Open **Settings → Plugins & MCP** and pick the **Workspace** the server belongs to. **Personal** is only for you. An organization's plugins are available to its members.
2. Choose **Add MCP server**. The dialog confirms the target: **Adding to your personal workspace.** or **Adding to your organization workspace.**
3. Keep **Remote** selected, then enter a **Name** and the **Server URL**.
4. Under **Authentication**, choose:
   - **Sign in or none**: Zuse detects whether the server needs you to sign in or is open to everyone.
   - **Bearer token**: enter the **Token**.
   - **Custom header**: enter the **Header name** and **Value**.
5. Choose **Add server**. If the connection fails, the dialog stays open with the error so you can fix the URL or key and try again.

Keys are encrypted on Zuse servers and never reach agent machines. Popular services may already be in the plugin catalog under **Browse plugins**. Prefer the catalog entry when one exists.

## 2. Add a local command

In your personal workspace, choose **Add MCP server**, switch to **Local command**, enter a **Name**, and paste the server's configuration into **MCP configuration (JSON)**. You can paste either one server object or a standard `mcpServers` object containing exactly one server. The name always comes from the **Name** field. Zuse starts the server and lists its tools before saving it.

For example, Paper Desktop provides a configuration like:

```json
{
  "mcpServers": {
    "paper": {
      "type": "stdio",
      "command": "/Users/you/.paper/bin/paper",
      "args": ["mcp"]
    }
  }
}
```

Use the actual command path supplied by your installation. `args` must be an array of strings and optional `env` values must be strings. Zuse runs the command directly, without a shell; pass each argument as a separate array entry.

Local servers belong to your signed-in account on this computer and appear only in your personal workspace. They are not shared with organization members or copied to cloud computers. Turn a connection off or remove it in **Plugins & MCP** to stop its server process.

For Paper, keep Paper Desktop running with a file open when reading or changing a design. See [Paper's MCP guide](https://paper.design/docs/mcp).

## 3. Import servers from this computer

**Settings → Plugins & MCP → Import from this computer** lists MCP servers already set up in the agent apps on this computer. Choose the ones agents should get in every chat, then choose **Import**. Imported servers appear under **Connected**.

## Verify the server

1. Start a new chat. A provider process that was already running may still have its old tool set.
2. Type `/mcp` in the composer to see the agent's MCP servers and your Zuse plugins, or ask the agent to list available plugins.
3. Ask the agent to use one known, harmless read-only tool from the server.
4. Approve the call if the chat's access mode requires it, and confirm that the result came from the intended server.

## Troubleshooting

- **The key is rejected:** check the header name and key against the server's documentation, then try again.
- **The server didn't offer sign-in:** it needs a key. Choose **Bearer token** or **Custom header**.
- **A plugin shows Needs authorization:** finish its sign-in from Plugins & MCP. Only one plugin sign-in can run at a time.
- **The local configuration is rejected:** it must contain a non-empty `command`, `args` as an array of strings, and string `env` values.
- **The agent cannot see the tools:** confirm that the server is listed under **Connected** in the workspace the chat uses, then start a new chat. A chat keeps the plugin workspace it first used.
- **A tool request is denied:** plugin availability does not bypass [access modes and permissions](/composer/modes-permissions/).
