## Goal

Give a local task enough precise context to begin useful work without pasting an entire repository into the conversation.

## Applicability

Use this workflow in the **desktop app**. File references are scoped to the checkout the chat uses. A provider's ability to interpret a particular attachment type can vary, so prefer repository files or plain text for critical instructions.

## Prerequisites

- Select the chat and checkout where the task should run.
- Confirm that the files you want are inside that checkout or are available on your computer.
- Keep secrets out of prompts and attachments unless the selected provider is permitted to receive them.

## Steps

1. Check which checkout the chat uses before adding context. The top bar shows its branch. A file in the main checkout can differ from the same path in a worktree.
2. Type `@` in the composer and search for a repository file or folder. Select the result to add a file chip. You can also drag a file from the **Files** panel into the composer.
3. Add external files with the composer's add menu (**Attach images or files**), by dragging them onto the chat, or by pasting them. Pasted screenshots and copied image data are attached as images. Each file can be up to 24 MB.
4. If the task starts from tracked work, open **Create from…** in the composer before the first message, switch to **Issues**, and choose the issue. Zuse attaches the issue as `issue-<number>.md` to the first message.
5. To reuse work from another session, drag its row from the sidebar onto the chat (**Drop to mention**). Zuse adds a mention of that chat to the composer.
6. In the message, explain why each item matters and name the expected outcome. For example: “Use `@src/auth/session.ts` as the implementation source, compare the attached failure log, then add a regression test.”
7. Send the message only after attachment chips have finished uploading.

For a large evidence set, place the material in a repository folder and reference only its entry points, or split it across focused messages.

## Verify the context

1. Before sending, confirm every intended file appears as a chip and no upload error was shown.
2. After sending, inspect your message in the timeline and confirm the file mentions and attachments appear as message chips.
3. Ask the agent to identify the files it will use when ambiguity would be expensive.
4. Check the **Files** panel or terminal to ensure referenced repository paths belong to the active checkout.

## Troubleshooting and recovery

- **The `@` search cannot find a path:** confirm the active project and checkout. Search is scoped to that checkout.
- **A file is rejected as too large:** the limit is 24 MB per file. Attach an excerpt, a compressed export, or a text summary instead.
- **The wrong version of a file was attached:** remove the chip, switch to the chat that uses the intended worktree, and add it again. File chips are not branch-independent.
- **The provider cannot use a binary format:** export the relevant content as text, Markdown, or an image and attach that instead.
