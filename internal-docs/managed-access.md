# Account-managed access client

The engine's `managed_access::AccountClient` uses Zuse's existing account API and `Account` lifetime. One client belongs to each engine core; RPC service clones share its proof-key and credential state. The account-control client, durable host link owner and account-authorized RPC transport are implemented. Managed connector supervision, automatic local transport restoration and environment-authenticated heartbeat publication are also implemented. Native and browser settings expose account sign-in, computer linking/unlinking, discovery and authorized-device revocation. Native Settings can open account-authorized computers in separate windows. Saved endpoint history is account-scoped and contains no credentials. Browser Settings can open a compatible account computer in its own tab, with controller-owned authorization and uploads.

## Available engine operations

- `ListAccountEnvironments` returns the signed-in account's linked computers, including endpoint, runtime, capability and public identity metadata.
- `ListAccountDevices` returns authorized client metadata.
- `ListAccountRoutes` reads remembered computer metadata from the local profile without an external account request. `RememberAccountRoute` and `ForgetAccountRoute` require the expected account subject and never grant or revoke host authorization.
- `BootstrapAccountConnection {environmentId, expectedSubject}` obtains a transient private connection capability for the selected host and exact protocol. This dedicated reply is excluded from automatic retries and ordinary settings/catalog state.
- `RevokeAccountDevice {clientId}` asks the account service to revoke one client. It is a write and is excluded from interrupted-request retries.
- `ManagedHostStatus` returns link metadata and the current account match, without credentials or public-key configuration.
- `WatchManagedHost` pushes that metadata on account, link, connector, heartbeat and shutdown changes. It is a profile-scoped read subscription; status changes do not poll the external account API.
- `LinkManagedHost {label}` validates the name and signed-in account, starts a missing loopback HTTP browser listener, then links the connected profile using its actual port on `127.0.0.1`. An existing incompatible listener is reported. The caller cannot substitute an arbitrary local target.
- `UnlinkManagedHost` disables local admission before making the remote unlink request. These link mutations are excluded from interrupted-request retries.

These operations belong to the connected profile and reject a foreign `targetDeviceId`. Reads are explicitly classified as retryable; they do not start local agents, connect to advertised endpoints or imply host reachability. Account errors do not close otherwise healthy engine RPC connections.

## Shared account-control implementation

The same client implements environment linking and client-bound connection bootstrap for the host owner. Linking obtains an account challenge, signs it with a profile-bound Ed25519 key and sends the public host identity. The advertised local origin is derived from the supplied loopback listener port, rather than an arbitrary caller URL. Receipts validate environment identity, public mint key, endpoint/origin correspondence and the managed tunnel hostname/token. Secret-bearing link and bootstrap receipts deliberately cannot be serialized into ordinary UI metadata.

The host key is created once in `managed-access/identity.json` beneath the current profile. Its versioned record binds the key to the device identity. Directory/file permissions are private on Unix; creation uses a synced temporary file and atomic no-clobber persistence. Restart reuses the public identity. Invalid, foreign and damaged records are reported instead of regenerated. The account API receives only the public JWK and signed proof.

Connection bootstrap uses an ephemeral P-256 proof key for the account lifetime. Proofs bind the method, target URL, fresh nonce and issue time; authenticated proofs also bind the access token hash. Token exchange and client registration share one admission gate. Cached access has monotonic and wall-clock expiry with renewal slack. A definitive authentication rejection invalidates that credential and permits one authentication retry; timeouts, server errors and redirects are never treated as permission to replay an action. The caller must supply the intended wire protocol version; the client does not claim compatibility with an unrelated protocol by default.

Every request captures the account cancellation lifetime and checks its subject before and after I/O. Sign-out, account replacement and engine account retirement cancel in-flight work and retire cached proof credentials on subsequent use. Refreshing an account token does not tear down a healthy application connection. Responses are streamed with a 1 MiB limit; HTTP has bounded connection/request deadlines and follows no redirects. Errors omit tokens, proof bodies, private key material and connector credentials.

## Host authorization and transport

`managed_access::host::Owner` belongs to EngineCore. Server and RPC clones hold only control handles. The owner's close cancels admission and established sessions even when those handles survive. Its private `managed-access/link.json` record binds the receipt to the profile device, account subject and API origin; it is atomically replaced with file mode 0600 and directory mode 0700 on Unix. Invalid or foreign records are reported and cannot be silently overwritten. Link configuration survives ordinary restarts. Another signed-in account cannot use or unlink it.

An unlink writes the disabled state and cancels existing host grants before sending the account-service write. A timeout or service error leaves that disabled record available for an explicit retry, including after restart. A confirmed unlink removes the record. No automatic link recreation is implemented. Sign-out cancels active account sessions; a different account cannot reactivate the saved authority.

Host admission verifies the API's Ed25519 signature using the saved public mint key, `connect+jwt` type, exact issuer, environment audience, matching environment ID, bounded nonempty subject, expiry and optional not-before time. Grant lifetime is bounded to one day and tracked with both wall-clock admission checks and a monotonic connection deadline. The API decides which account subjects may access a shared environment; the host does not reinterpret an arbitrary caller-provided subject as authorization.

Both the foreground server and a Settings-owned browser listener expose `/api/account-rpc`. The client first sends a text frame containing `{"protocol":"zuse-rpc-json-v1","connectToken":"…"}` within ten seconds. No canonical RPC dispatch runs before successful grant verification. The server acknowledges with `authenticated`, `protocol`, `deviceId` and `expiresAt` (milliseconds), then exchanges the existing canonical RPC frames. The token is never a query parameter, browser session cookie or ordinary RPC parameter. Same-origin browser clients and the currently linked managed HTTPS endpoint remain accepted. A cross-origin browser client must explicitly offer the account subprotocol and use a normalized HTTPS origin (HTTP is restricted to loopback). This exception applies only to the account socket, whose bounded first-frame grant is the sole authorization; cookies and listener tokens do not authorize it. Cookie-authenticated `/api/rpc` retains its Origin restriction. Native clients may omit Origin. Account, host and listener cancellation, as well as grant expiry, close the socket and retire dispatch/subscriptions. Requests cannot target another execution device.

This endpoint uses HTTPS/WSS transport through the managed endpoint; it does not replace or downgrade the existing Noise paired endpoint. A client must explicitly select this account protocol. An older application's wire protocol is not assumed compatible merely because a grant was issued. The current status distinguishes a connector process from a reachable endpoint. Native/browser account destination selection, saved metadata and in-place grant renewal are implemented. Account discovery publishes this protocol as wire version 1 with the explicit `zuse-rpc-json-v1` capability; the older application wire is not advertised.

## Managed connector runtime

A saved enabled link restores a loopback HTTP browser listener when the native app or headless daemon boots. The foreground browser server supplies its own actual listener. Listener registration wakes one host supervisor; account mismatch, sign-out, disabled link and listener shutdown prevent connector admission. The supervisor reconciles the current listener port through the existing environment heartbeat before exposing it, so ephemeral listener ports can change across restarts. No account sign-in service or second execution engine is introduced.

The installer pins cloudflared 2026.7.2 for Linux/macOS x86-64 and arm64 using the [published release checksums](https://github.com/cloudflare/cloudflared/releases/tag/2026.7.2). Downloads use HTTPS with bounded redirects, deadlines and a 128 MiB streamed limit. Linux caches the checksum-verified executable. macOS retains the verified archive and extracts only its fixed `cloudflared` member with bounded output; it does not trust an editable extracted-hash manifest. Runtime files are private and the connector has no automatic updater or PATH fallback.

Each launch uses a private 0600 temporary token file under the 0700 managed-access directory. Process arguments contain only its path. Inherited tunnel-token environment overrides are removed; connector stdout/stderr are not copied into application logs. Exits restart with bounded backoff. Stop sends SIGTERM to the owned child, waits two seconds, then kills and reaps it if needed. The token file is removed after the child exits. Linux also installs a parent-death kill with a parent-identity check. Startup recovers stale token files and matches the complete profile-specific binary/token-file command before retiring an orphan; it never kills by process name alone. Physical macOS crash/restart acceptance remains pending.

Heartbeat uses the private environment credential, never the UI's account bearer. The successful origin reconciliation counts as the initial heartbeat; no duplicate startup beat is sent. Healthy reporting runs every 30 seconds, detects elapsed wall time after resume and backs off on failure. A reporting outage preserves the running connector. Authentication rejection persists a disabled link, retires grants and stops its connector. A service-requested credential cleanup also stops exposure without acknowledging cleanup or deleting unrelated local provider credentials; execution of that account command remains an explicit compatibility item.

`ManagedHostStatus.tunnelRunning` reports a local child process, and `lastHeartbeat` reports the latest acknowledged account heartbeat. Neither proves public tunnel reachability. Local lifecycle fixtures exercise the actual server listener, account HTTP client and an owned child process, including changed-port reconciliation, private token argv/file handling, sign-out, same-account restart and disabled restoration after service revocation. Pin integrity and orphan command/file recovery have focused checks. The ignored `pinned_installer_runs_the_verified_connector` test is run explicitly for release-download/execution acceptance rather than adding external downloads to every test run. Current evidence is recorded in `.context/managed-connector-{engine-final,install-final,socket-final,native-final}.log`. No deployed account/tunnel or physical Mac acceptance is claimed by these checks.

## Settings and private invitations

Native Devices settings and browser Remote access settings expose the same account and host controls. They use the existing framed cards and button styles. A host subscription updates startup, process, account and error state without account-service polling. Computer and authorized-device catalogs load only for a signed-in account, refresh explicitly and reconcile after access actions. Account/profile changes retire old reads, clear account-scoped rows and prevent late responses from replacing current data. Interrupted mutations are reconciled from reads and never replayed automatically. Native access cards share their layout helpers with the existing pairing cards.

After linking, `CreatePairing` prefers the managed HTTPS address while the host's account matches and the saved link is enabled. Its existing private Noise invitation then works with the existing native/browser pairing flow. Sign-out, disabled access and account replacement remove that address from new invitations. Native link actions refresh the existing invitation controls after starting the local listener. This makes managed hosting usable with private invitations while direct account-grant destination selection and the saved route catalog are still being implemented.

Current controls verification: nine focused engine scenarios, one GPUI browser state scenario, native desktop/CLI/viewport checking, the production WASM build and the actual host-server build pass. `node scripts/acceptance/managed-access.mjs` exercises the actual compiled GPUI browser and a disposable engine, opens Remote access, confirms one metadata subscription, and records zero account-catalog calls while signed out and zero agent writes. It captures `.context/managed-controls-settings.png`; receipts are `.context/managed-controls-{engine-final,viewport,native,web,server-build,browser}.log` and `managed-controls-browser-acceptance.json`. The normal preview was refreshed using its existing profile after confirming it had no sessions or child processes; `managed-controls-preview-update.json` confirms preserved device identity and working host status. Signed-in cloud service, deployed tunnel and physical desktop acceptance remain separate gates.

## Native account destinations and saved history

Native Settings offers Connect for a non-current computer advertising both wire version 1 and the explicit account JSON capability. Discovery wins over remembered metadata. Each destination opens in its own window and authenticates through the original controller engine; it cannot silently fall back to the local engine. Initial bootstrap captures the signed-in subject, verifies the selected host identity over its authenticated RPC socket, then remembers its public endpoint. A failed optional history write does not discard a working connection. Older wire versions require an app update.

The account socket renews its short-lived authorization in place before expiry. The host requires the same subject and execution device and checks the latest grant for each RPC. Renewal preserves existing subscriptions. Transient bootstrap failures back off within the original grant lifetime; stale non-extending grants also back off. Authentication acknowledgement, ping/pong and authorization requests have deadlines. Socket loss or an endpoint change exposes an explicit Retry and preserves unsent edits; no canonical action is replayed and no route switch is hidden. Auxiliary media sockets obtain their own grants and share the controller account cancellation lifetime without closing the main channel when they finish. Sign-out, subject changes and definitive bootstrap rejection retire the shared connection source. Service-issued grants remain valid until expiry unless their host/account lifetime is also retired.

History lives beneath the profile's `managed-access/routes` directory, in bounded, atomically written private files keyed by account subject hash. Each record stores environment ID, label, verified origins, protocol snapshot and timestamps. It stores no access, refresh or connection tokens. Native/browser settings merge this local metadata with fresh discovery and offer Forget saved; forgetting removes only the current account's local history. Every future connection still needs fresh account authorization, including when discovery is unavailable.

The integration checks pass three real WebSocket scenarios, eleven focused engine scenarios (one external installer scenario remains explicitly ignored in this group), the settings account-state regression, the native desktop/CLI/viewport check and the production WASM build. Evidence: `.context/account-connections-{socket-tests,engine-tests,viewport-tests,native-final,web}.log`. The native transport scenario crosses the initial grant expiry on the same subscription and verifies no repeated write; another scenario rejects renewal as a different subject. These are local fixtures, not live account-service, deployed tunnel, rendered native-window or physical platform acceptance.

## Browser account destinations

Connect in the controller's Remote access settings opens a separate same-origin tab. Its URL carries only environment ID, account subject and label; a successful public target write moves that metadata to session storage and clears the fragment. If storage is unavailable, the public fragment remains so reloading cannot accidentally select the local engine. Invalid explicit destinations remain invalid across reloads. The child inherits an existing controller pairing when present and immediately retires its opener. Connection grants never enter URLs, session/local storage, preferences or saved history.

Each tab owns a separate authenticated controller socket and account-status subscription. A bounded request broker obtains fresh private grants through the engine, verifies the expected subject and cancels outstanding calls when it retires. The destination acknowledges its grant and answers an explicit canonical engine-identity query before workspace traffic starts. Grant refresh, responsiveness challenges and timeouts run on the destination socket without resubscribing the workspace. Account changes or definitive authorization rejection close all sockets using that controller. Ordinary network loss uses the existing browser reconnect and interrupted-request policy: fresh authorization and host verification precede reopening reads; uncertain actions are never replayed.

File-picker and pasted uploads reuse the same chunk/commit implementation for paired and account destinations. Each account upload owns an auxiliary socket and grant; closing it does not retire the workspace connection. Browser microphone/WebRTC signaling continues through the selected workspace transport. Live voice and physical file-picker acceptance are not established by this milestone. Remote access settings expose Return to controller independently of the destination's account sign-in state. Opening another account destination from an account-connected tab remains unavailable; use its controller tab.

Four real socket scenarios pass, including cross-origin account protocol selection, credential-only refusal before a grant, and unchanged Origin refusal on `/api/rpc`. The actual compiled GPUI browser check uses a response fixture only at the account/endpoint boundary and the disposable real engine for workspace traffic and file chunks: it opens a tab, retires the opener, renews on one subscription, verifies exact uploaded bytes on the selected host, and closes connections on controller account replacement. It also covers storage failure and invalid-target reloads without local fallback. Evidence: `.context/browser-account-{socket-tests,native-check,web-build,server-build,runtime}.log`, `.context/browser-account-runtime-acceptance.json`; run `node scripts/acceptance/account-connections.mjs` after building web and `zuse-server`. No account tokens, live tunnel, physical platform or paid agent/provider calls are needed for this check. Live deployed account authorization, paired-controller account tabs and complete multi-device acceptance remain open.
