# Local Git controls

Native and browser Changes panes use the same GPUI Git panel. The panel sits above the diff in Review and History as one row: branch, ahead/behind, the one next step as a filled button (Publish, Pull, Push, or Open PR), and an overflow menu for everything else. Files are checkbox rows, where checked means staged. The commit box appears only when there are changes. Git opens expanded, loads when a checkout is selected, and subscribes to engine-owned status while its Changes view is active. Filesystem events trigger debounced updates, with a two-minute reconciliation tick. Fetch updates remote-tracking refs without integrating changes. Stage or unstage individual files or all currently listed files, enter a commit message and commit staged changes. Push sets the first upstream to origin when none exists. Pull allows fast-forward integration only. Branch actions create from the current checkout or switch by name; Git rejects conflicting checkout changes.

The engine exposes `WatchGitWorkspace {chatId, cwd}`, `GetGitWorkspace {chatId, cwd}` and `GitWorkspaceAction {chatId, cwd, checkoutId, revision, operation}`. Operations are stage/unstage with literal paths, commit with a message, fetch, push, pull, createBranch, switchBranch and createPullRequest. See [pull requests](pull-requests.md) for hosted creation and receipt handling. Requests route to the selected thread's owning device. The engine verifies that the thread still owns the canonical checkout, rejects archived targets, serializes its own controls per checkout, and checks the displayed revision before a mutation. The revision covers HEAD, branch/upstream metadata, status and the Git index bytes. It does not freeze external editors or Git processes: staging takes the file's current working bytes, and Git's index/ref locks remain authoritative during external races.

Paths come from complete Git status and pass as NUL-delimited literal pathspecs. Staging preserves unrelated index entries; unstaging preserves working files and supports unborn repositories. Committing uses the staged index without automatically staging other changes. No action force-pushes, resets working files or integrates a merge/rebase on pull. User Git hooks, signing configuration and credential helpers remain in effect; terminal password prompts are disabled. Git command output is drained concurrently into bounded captures, error text is redacted, commands have a two-minute timeout, and index fingerprinting streams through an 8 KiB buffer.

An admitted mutation remains engine-owned if its caller disconnects. Its caller must read current state instead of repeating an uncertain action. Both frontends fence old thread/host responses. A failed or lost mutation receipt triggers a status read and preserves the notice. Archived threads expose their saved review through the existing read-only Changes view; Git mutation controls require unarchive.

Two real-Git RPC scenarios exercise literal filenames, initial staging/unstaging, selected staged commits with untouched working edits, stale index rejection and archived admission. A local bare-remote scenario within that suite covers first push/upstream creation, branch actions, fast-forward pull and rejected divergent push/pull without rewritten local commits. Shared GPUI state scenarios cover eager loading, stalled reads, stale thread receipts, action uncertainty and archived controls. These are local integration and state checks; full rendered UI, hosted remote credentials, physical Mac/Linux and packaging acceptance remain separate requirements.

Status reads have a thirty-second UI deadline; mutations have a 150-second receipt deadline. A timeout preserves action uncertainty and reads current status instead of replaying the action. Late receipts cannot replace a newer target or request.

## Shared refresh ownership

`source_control_refresh.rs` owns demand, retained snapshots, bounded entries, retry backoff, per-resource staggering, and generation fences. Native and browser Git panels consume `SourceControlFrame` updates with separate local and remote error/freshness fields. A screen has no status polling timer. Worktree subscriptions authorize their chat and checkout on entry and close if that chat is archived, removed, or moves. Watch registration runs on the blocking pool; shared watcher rescan events cover registration gaps. Large directory trees retain the existing watcher budget and reconciliation fallback.

`git_fetch.rs` coalesces requests by common Git directory, remote name, and URL. Linked worktrees share a bounded fetch writer, with four network fetches across the engine and one writer per repository. Active Git subscriptions request background fetches roughly once a minute; no subscribers means no periodic work. The cache lingers for thirty seconds after demand leaves. Explicit refresh bypasses success/backoff freshness and joins an already running fetch. Git controls, FetchAll, and compatibility branch-graph refreshes use this path. Background fetches disable automatic maintenance and tags, preserve local changes, and retain an admitted writer if a client disconnects. Transcript cards request local branch graphs without fetching.

Local file status publishes before full patch capture. A patch failure cannot erase a successfully captured file status. Watch bursts have a maximum wait, so continuous edits cannot starve reconciliation. User writes still take the checkout mutation gate and require the displayed revision; watcher reads never substitute for admission checks.

## Status cost

One `git status --branch` supplies files, branch, upstream and divergence, so a snapshot runs that plus concurrent HEAD and index-path reads. Background fetches pass `--no-write-fetch-head` because Git writes that file unlocked and a concurrent pull could fail on it. Worktree invalidations settle for 150 ms. Sidebar diff sizes come from an app-level `WatchCheckoutDiffs {summaryOnly: true}` subscription per device, with patches stripped, independent of any open Changes view. Diff capture settles for 150 ms, or twice the last capture's duration up to 500 ms on large checkouts.
