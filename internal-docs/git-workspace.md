# Local Git controls

Native and browser Changes panes use the same GPUI Git panel. Expand Git to inspect staged/unstaged files and upstream counts. Stage or unstage individual files or all currently listed files, enter a commit message and commit staged changes. Push sets the first upstream to origin when none exists. Pull allows fast-forward integration only. Branch actions create from the current checkout or switch by name; Git rejects conflicting checkout changes.

The engine exposes `GetGitWorkspace {chatId, cwd}` and `GitWorkspaceAction {chatId, cwd, checkoutId, revision, operation}`. Operations are stage/unstage with literal paths, commit with a message, push, pull, createBranch and switchBranch. Requests route to the selected thread's owning device. The engine verifies that the thread still owns the canonical checkout, rejects archived targets, serializes its own controls per checkout, and checks the displayed revision before a mutation. The revision covers HEAD, branch/upstream metadata, status and the Git index bytes. It does not freeze external editors or Git processes: staging takes the file's current working bytes, and Git's index/ref locks remain authoritative during external races.

Paths come from complete Git status and pass as NUL-delimited literal pathspecs. Staging preserves unrelated index entries; unstaging preserves working files and supports unborn repositories. Committing uses the staged index without automatically staging other changes. No action force-pushes, resets working files or integrates a merge/rebase on pull. User Git hooks, signing configuration and credential helpers remain in effect; terminal password prompts are disabled. Git command output is drained concurrently into bounded captures, error text is redacted, commands have a two-minute timeout, and index fingerprinting streams through an 8 KiB buffer.

An admitted mutation remains engine-owned if its caller disconnects. Its caller must read current state instead of repeating an uncertain action. Both frontends fence old thread/host responses. A failed or lost mutation receipt triggers a status read and preserves the notice. Archived threads expose their saved review through the existing read-only Changes view; Git mutation controls require unarchive.

Two real-Git RPC scenarios exercise literal filenames, initial staging/unstaging, selected staged commits with untouched working edits, stale index rejection and archived admission. A local bare-remote scenario within that suite covers first push/upstream creation, branch actions, fast-forward pull and rejected divergent push/pull without rewritten local commits. One shared GPUI state scenario covers stale thread receipts, action uncertainty and archived controls. These are local integration and state checks; full rendered UI, hosted remote credentials, physical Mac/Linux and packaging acceptance remain separate requirements.
