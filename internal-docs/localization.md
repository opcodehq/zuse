# Localization

Zuse bundles English (`en`), French (`fr`), German (`de`), Simplified Chinese
(`zh-Hans`), Traditional Chinese (`zh-Hant`), Japanese (`ja`), and Korean (`ko`).
Catalogs work without a translation service. Missing or invalid translations fall
back to English. Non-English translations remain drafts until native-speaker review
and screen QA are recorded; importing a correction does not certify every message.

## Runtime and preferences

`crates/i18n` owns Fluent resources, generated accessors, language negotiation,
English fallback, and ICU number/date presentation. Parsed Fluent bundles and ICU
formatters are cached by locale. The cache contains immutable resources, not a
selected language. Each GPUI App owns a localization context; desktop views and
browser-compatible components within that App share it. Separate app instances
can use different languages.

Desktop stores `language` in its existing `ui-settings.json`. It publishes a new
language only after an atomic settings write succeeds. Browser stores its choice
in `zuse.language.v1` in localStorage; storage events synchronize other tabs.
Browser preference writes are acknowledged before activation, and failure retains
the previous language. Browser storage is independent of the selected engine and
account. System mode reads OS preferences on desktop and `navigator.languages` in
the browser. Explicit Chinese scripts take precedence over region; Taiwan, Hong
Kong and Macao select Traditional, while China, Singapore and bare `zh` select
Simplified. Unsupported languages fall back to English.

The CLI accepts `--language` and `ZUSE_LANGUAGE`; precedence is flag, environment,
system. Interface language does not change command names, flags, exit codes,
URLs, credentials, machine-readable output, MCP traffic, logs, agent instructions,
user content, or model/provider identifiers. External provider diagnostics may
retain their original wording.

## Editing interface copy

Editable resources are `crates/i18n/locales/<locale>/<feature>.ftl`. Keep imported
feature keys stable. Rust-specific additions live in `native.ftl` and CLI messages
in `cli.ftl`. Add context comments explaining ambiguous actions and variables.
Translate a complete message with named values instead of concatenating sentence
fragments. Use Fluent selectors for plurals, terms for shared vocabulary, and
attributes for related visible/accessibility labels. Keep paths, product names,
code, keyboard legends, and technical identifiers intact.

Accessors are generated by the crate's build script. For example:

```rust
use zuse_i18n::{Localizer, Locale, messages};
let language = Localizer::new(Locale::ZhHans);
let label = messages::common::save(&language);
let count = messages::simulators::summary_devices_plural(&language, 3);
```

A missing argument is a Rust compilation error. In views, use the App's
`localization::message(cx, accessor)` (usually imported as `tr`) rather than
constructing a localizer or storing translated text in protocol/domain objects.
Pure helper elements can use `localization::element(accessor)` to resolve their
text when rendered. Switching language refreshes views without recreating the
workspace or clearing its drafts.

Imported suffix keys remain available for fidelity and source mapping. Prefer the
complete `*_plural` accessors for new count messages. Rich component markers are
retained as translator data; render them only through explicit component mappings,
never as HTML. Format presentation numbers and Gregorian civil dates with
`Localizer::number` and `Localizer::date`; retain explicit units, currencies and
time-zone ownership at the call site.

## Preserved Chinese corrections

The import pins the older desktop catalogs at
`a0155d2dd11f07495a99d3737c9bd40a5c8b4508`. Chinese catalogs come from liuweifeng's
[PR #952](https://github.com/swarajbachu/zuse/pull/952), including follow-up commits,
at `0526c0854b75501b5d7dc7d917a06fd2c7be4231`. The PR was open at import time; its
changes are included directly, independently of whether upstream has merged it.
`migration.json` maps all imported keys and records source revisions, contributor
attribution, original hashes, locale-specific plural exceptions and rich markers.
Website [PR #872](https://github.com/swarajbachu/zuse/pull/872) supplies related
terminology context; website catalogs are not imported into the Rust application.

Maintain Simplified and Traditional independently. Do not regenerate corrected
catalogs with machine translation or automatic script conversion. In particular:

| Concept | Simplified | Traditional / Taiwan |
| --- | --- | --- |
| Agent | 智能体 | 代理程式 |
| Session | 会话 | 工作階段 |
| Project / repository | 项目 / 仓库 | 專案 / 存放庫 |
| Git worktree | 工作树 | 工作樹 |
| Payment checkout | 结账 | 結帳 |
| Checks passed | 通过 | 通過 |
| Via / through | 通过 | 透過 |
| Apply a change | 应用 | 套用 |

Preserve context-sensitive corrections such as `3 次工具调用`, payment checkout
versus Git checkout, and `通過` versus `透過`. Review upstream suggestions against
the actual calling screen: a bot suggestion is not automatically an approved
terminology change. New Rust-specific copy is separately drafted and does not
overwrite the imported contributor text.

## Review workflow

Run `python3 scripts/check-localization.py --update` after English changes. It
updates review metadata only. Affected messages, including users of changed shared
terms, become `needs-review`; other reviews remain valid. An edited reviewed
translation also needs renewed review. The tool never rewrites Fluent files or
promotes a draft.

`review.json` defaults translations to `draft`. To review an individual message,
record `status: reviewed`, the reviewer, screen QA evidence, and the current
`sourceHash` and `translationHash` from the checker. Hashes include referenced
messages and terms. Catalog availability and review status are separate.

The importer is a one-time conversion utility. It refuses to overwrite existing
Fluent resources. Use `--output /an/empty/directory` to reproduce or inspect an
import. The ignored migration-fidelity test audits the original import against its
pinned hashes; it is intentionally separate from normal CI so later intentional
translation edits are not forbidden.

## Offline fonts and checks

Regional Noto Sans CJK subsets provide language-appropriate interface glyphs.
A full CJK fallback and a complete Hangul fallback support user text beyond the
catalogs. The full fallback
includes Latin metrics required by the renderer. Assets, licenses and source
fingerprints live in `crates/viewport/assets/fonts`; the subset script accepts the
four pinned Noto OTFs plus `DroidSans.ttf` and `DroidSansFallbackFull.ttf`.
Rebuild with `python3 scripts/subset-localization-fonts.py <source-directory>` when
new copy introduces characters absent from a regional subset. FontTools is a
maintenance dependency, not a runtime dependency.

Useful checks:

```sh
python3 scripts/check-localization.py
python3 -m unittest discover -s scripts -p test_localization.py
cargo test -p zuse-i18n
cargo test -p zuse-cli --bin zuse-server localization_tests
cargo test -p zuse-viewport --lib localization::tests
cargo test -p zuse-viewport --lib language_fonts::tests
cargo test -p zuse-ui --lib localization::tests
```

The Fluent checks cover syntax, references, variables, plural defaults, key
coverage and generated accessors, while allowing locale-specific plural forms.
`Localizer::expanded()` provides expanded English in development builds without
changing interpolated user values or rich markers. Review actual desktop/browser
screens at narrow and wide widths in every language. Check Chinese glyphs, IME
composition and Enter-to-confirm, keyboard navigation, offline startup, rapid
switching, restarts, multiple tabs/windows, and storage failure before certifying
a translation. Mobile, marketing-site implementation and translated documentation
remain separate work.

## Implementation validation (2026-11-02)

The migration audit checked all 26,271 imported locale/key pairs against their
pinned literal text, placeholder and markup hashes. Automated tests cover locale
negotiation, independent contexts, fallback, formatting, plural/attribute access,
Chinese correction examples, review invalidation and browser draft preservation.
The browser WASM build was exercised offline in Chrome with all seven languages,
language persistence after reload, cross-tab storage synchronization, CJK glyphs
and wrapping language controls at 800px width. Browser editor composition tests
cover cancellation, field changes, focus loss, duplicate-commit prevention,
trusted Unicode IME updates and Enter confirmation without submitting the composer.
An unsent Chinese draft survived
live switching through every language.

This is not a native-speaker certification. Newly drafted copy still needs native
review; less common flows and external diagnostics can still display English.
Desktop runtime and physical IME candidate/confirmation checks remain pending.
The development VM lacks WebKitGTK; desktop Rust source and test type checks use
a temporary, untracked build-helper bypass, not a functioning native browser
helper. CI retains the real WebKitGTK build on Linux and the macOS native checks.
